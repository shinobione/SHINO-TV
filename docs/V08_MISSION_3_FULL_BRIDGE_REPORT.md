## Isolated native build

`experiments/v08_full_bridge/platformio.ini` is a separate project. Its default is `bridge_baseline`; `bridge_preparse` is explicit opt-in. Both use espressif8266 4.2.1, Core 3.1.2 (`3.30102.0`), ESP12E, DIO/4MB/eagle.flash.4m3m.ld, low-memory/low-flash lwIP, Xtensa GCC 10.3.0 and `-fstack-usage`. Both pin ArduinoJson 7.4.3, GFX 1.6.4 and AnimatedGIF 2.2.0; production's last two caret ranges are not changed. This is a controlled equivalent comparison, not an installed-image rebuild.

The pre-build hook copies only `git ls-files firmware/src firmware/include firmware/lib` into ignored `.pio/shadow`, records source SHA-256 provenance, supplies public inert policy fixtures, and fixes the same version label in both environments. It never reads the ignored production policy or owner backups. OEM restore, filesystem migration and native signed OTA are disabled. Only global main entry definitions are renamed in the copy. An identical zero-initialized volatile startup guard retains the complete first-boot bridge/display link graph while the ordinary research entry points do not call it. The guard is a compile/link research device, not an installation safety mechanism; these images have never been executed and must not be installed.

The experiment fingerprints the six pinned core files and materializes the existing Mission 2 overlay in `.pio/pinned_overlay`. Copied WebServer includes resolve to that overlay consistently, including recursive template includes; its MIME implementation is built from the same copy. Installed packages and tracked firmware are unchanged. Native `nm` confirms `FirstBootBridge::run/loop`, the one linked anonymous bridge server and `_v08ReadFirstLine` in the experiment; the baseline lacks the preparse symbol. Both full variants link successfully. Media remains terminal deny-all before legacy parsing, without a registered media handler or cryptographic verifier.

Reproduce with `pio run -d experiments/v08_full_bridge -e bridge_baseline -e bridge_preparse`, then `python tools/v08_m3_resource_report.py`. The [resource report](V08_MISSION_3_RESOURCE_REPORT.md) records exact measurement classes and exclusions. ## Compatibility and limitations

The 130-byte global line cap intentionally narrows legacy acceptance. Ordinary bounded bridge URLs pass; arbitrary long historical targets do not have exact acceptance parity. Scanning the entire once-decoded line conservatively also denies a legacy query that mentions `/api/v2/bridge/media`, and the `mediax` prefix; this is measured research policy, not approved production behavior. A raw namespace candidate can never reach `onNotFound`, a metrics handler or an upload callback.

Legacy headers and bodies retain uncapped String allocation, duplicate overwrite and handler-after-body ordering. The first-line absolute timeout does not bound generic headers/body, auth, callback, TCP buffering, rendering or loop starvation. The Basic probe additionally preserves the core's acceptance of `Basic!` followed by a valid credential encoding: the six-character skip is not a strict scheme delimiter check. No Basic/Digest behavior is silently repaired. Historic V0.5 eight `test_gap_*` defect cases remain untouched.

Initial local build failures were caused by broad entry-point macro renaming and missing recursive overlay include paths. They were corrected only in the generated-shadow tooling; final links passed. An initial host package import and missing String writer seam were also corrected before final tests. The Windows broad tools suite still has its pre-existing compiler and symlink environment failures, recorded honestly in the gate.
