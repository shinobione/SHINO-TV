# SHINO // TV V0.6 — native firmware source audit

**28 September 2026. Source and offline tests only. No device contact, new receiver, firmware build, upload or installation.** This is a design gate for a possible later media receiver, not permission to change the installed SmallTV.

## Existing architectural contracts and integration points

| Area | Source-backed current behavior | Exact future seam and gate |
|---|---|---|
| HTTP owner | One `ESP8266WebServer server(80)` in `FirstBootBridge.cpp:67`; routes registered in `run()` at `:398-459`; `loop()` calls `server.handleClient()` at `:468-480`. Unknown paths receive authenticated 404. | Any separate, versioned media route would have to be deliberately registered in **this** owner, preserving every current route and the single port-80 listener. Do not activate it in this audit. Its work must be bounded so the cooperative loop can still paint stale/fresh metrics and feed the watchdog. |
| Authentication | `requireAuth()` (`:159-163`) uses the existing per-build HTTP Digest secret; POST metrics calls it first (`:251-253`). `browserSessionValid()/issueBrowserReadSession()` (`:93-157`) create two volatile peer-IP-bound, two-hour read sessions after Digest GET `/`. Cookies are accepted only for dashboard/UI/metrics GET and OTA capability GET (`:399-421`), never POST or OEM return. | Media write authorization needs a route-specific real Digest/nonce/replay/CSRF design and negative tests. Never promote the browser read cookie, track key, CRC32 or V0.5 boolean to write authority. Assess the shared `ESP8266WebServer` Digest nonce and concurrent Windows/browser behavior before choosing a route. |
| Request body | `acceptMetrics()` (`:251-272`) authenticates, copies `server.arg("plain")` to a `String`, rejects lengths outside 16..384, deserializes ArduinoJson, then calls `FslessMetrics::apply`. This bounds application parsing **after** the server has parsed the request. | A media handler needs a verified preallocation/framing limit and bounded read time **before** a 512-byte tile or 512-byte metadata reaches application memory. `server.arg("plain")` and existing multipart upload handling are not evidence of pre-body bounds. Inspect/test the pinned core's parser or design an independently reviewed bounded ingress without a second active listener. |
| Four metrics | `FslessMetrics::apply()` in `firmware/src/boot/FslessMetrics.cpp:25-63` validates typed, finite ranges and builds `Snapshot next{}` before replacing the single RAM state. Invalid samples preserve the last good sample and its timestamp. `stale()` (`:67-69`) is true before first sample or after **more than** 6000 ms, using unsigned `millis()` subtraction. `describe()` (`:71-89`) reports state/TTL without storage. | Media state must be separate from `FslessMetrics::state`; no media fields in numeric POST/GET. Preserve `telemetryNeedsRedraw`, four values and the existing freshness/error behavior under malformed media, transfer expiry, disconnect and rendering failure. |
| Native display | `FirstBootBridge::paintCard/paintNativeDashboard()` (`:285-374`) draws four 108×108 cards using `DisplayManager::getGfx()`; it repaints changed cards and yields after each. `loop()` (`:468-480`) paints on a valid sample or stale transition, throttled to >=250 ms. `DisplayManager.cpp:35-36,210,241-383,550` owns static SPI/ST7789 objects, vendor RGB565 init and rotation 0. `DashboardV2.h:9-31` defines 240×240 geometry. | A possible overlay compositor would enter adjacent to `paintNativeDashboard()` and the loop's draw scheduling, with an explicit return to all four cards at five seconds. Ensure one LCD owner, no full 115,200-byte frame, bounded text/pixel work, and a redraw on overlay expiry even if metrics do not change. PC simulator output cannot prove ST7789 byte order, crop/scale, timing or visual fit. |
| Heap observer | Default `esp12e` has no `SHINO_ENABLE_HEAP_DIAGNOSTICS`; opt-in `esp12e_heap_diagnostics` alone sets it (`firmware/platformio.ini:51-56`). `ShinoHeapDiagnosticCandidate.h:16-64` reads `ESP.getHeapStats` after existing loop work, never inside status serialization. `NativeOtaHeapReview.h:33-69` retains first/latest/lowest free/lowest largest block/highest fragmentation for at most 1024 valid samples; `NativeOtaHeapSampleCadence.h:15-39` attempts at most once per second without catch-up. | Use it as bounded historical observation, not an allocation guarantee. It misses shorter HTTP/render peaks, stops after saturation, and default firmware has no observation object. A future candidate needs phase-specific peak and largest-free-block evidence while metrics/browser/media contend. |
| Wi-Fi and interruption | `FirstBootBridge::run()` (`:379-395`) sets `WiFi.persistent(false)`, creates private WPA2 AP with at most two clients, turns Wi-Fi off and shows an error on AP failure. There is no active STA/HTTP client in this boot profile. `loop()` is cooperative; `handleClient()` precedes paint, OEM tick, heap sample, watchdog feed and `yield()`. `NativeOtaNetworkPump.h:3-81` is a disconnected compile-only review helper, not a live media reader. | A slow/partial HTTP request can delay metric redraw and watchdog service; pinned core parser wait/buffer limits and interruption behavior are not established here. Future host tests must cover slowloris, partial read, FIN/abort, replay, transfer timeout, POST metrics during media, browser GET and AP failure. No device call in this audit. |
| Flash, FS and OEM | `firmware/platformio.ini:18-47` pins ESP8266 platform/core, DIO, 4 MB, `eagle.flash.4m3m.ld`; `board_build.filesystem=littlefs` is a build setting, **not a first-boot mount**. `main.cpp:123-126` bypasses normal LittleFS/EEPROM/config/scene code; `FirstBootBridge.cpp:38-64,202-240` compile-forbids native signed OTA/FS migration and labels FS geometry as inferred. `FactoryRollback.cpp:13-38,75-176` keeps a separate policy-gated, Digest-protected exact OEM application-only return path with `Update.begin/write/end`, MD5, size/flash checks and deferred restart. Default policy generator disables restore; private owner policy may enable it. | Media design must not change flash layout, mount/format FS, persist media, alter OEM-return policy or introduce generic firmware write. OEM return is application-only, requires an already running bridge, and cannot restore original FS/settings or a nonbooting device. Existing write-capable private return must remain isolated from media auth and parser paths. |

The active firmware has **no active HTTP client** to fetch art or music. `SceneManager`'s legacy `HTTPClient` path belongs to the compile-blocked normal profile. The PC-local V0.4 bridge can collect media without changing this device contract.

## Allocation inventory and limits

| Item / lifetime | Explicit size or allocation | What remains unmeasured |
|---|---:|---|
| V0.5 PC proposal (`media_wire_v1.py:21-27,51-79,132-179`) | 64×64×2 = **8192 B** RGB565 little-endian; 16×512 B chunks; <=512 UTF-8 metadata | This exists on PC/host emulation only. A native receive buffer, copy count and parser are not defined. |
| Prospective native payload floor | 8192 + 512 + 512 = **9216 B** if three independent buffers coexist | HTTP framing, auth, ArduinoJson, `String` copies, SPI drawing, Wi-Fi stack and alignment add to it. A retained displayed cover plus new staging cover could require **16,384 B** for pixels alone. Never infer safety by subtracting this floor from observed free heap. |
| Current metrics state | One static `FslessMetrics::Snapshot` (`FslessMetrics.cpp:7`, header `:9-20`); `Snapshot next{}` on stack during validation | ABI padding, ArduinoJson document capacity and HTTP library body/argument copies in `acceptMetrics()` are unmeasured. |
| Current HTTP/browser | Static `ESP8266WebServer` and two `BrowserSession` objects (`FirstBootBridge.cpp:67,84-90`); dynamic `String` cookie/header/token/JSON/response in `:93-272` | WebServer/lwIP per-connection allocations, Digest processing, request-body buffering and allocation failure behavior require core-level measurement. |
| Current LCD | Static `Arduino_HWSPI` and `Arduino_ST7789` (`DisplayManager.cpp:35-36`); four small `Card` stack objects and fixed draw caches (`FirstBootBridge.cpp:276-374`) | Library internals/SPI DMA allocations and worst paint time are not measured. Source shows direct primitive drawing, no application-owned 240×240 framebuffer. `DisplayManager::drawTextWrapped` can use substantial fixed stack arrays; avoid calling it for every media frame without stack review. |
| Optional heap observer | Fixed summary/cadence; `static_assert(sizeof(Candidate)<=96)` in `ShinoHeapDiagnosticCandidate.h:65-67` | Sampling is post-work and at 1 s maximum cadence; no transient peak guarantee. |
| Owner-reported installed V2.1 sample | Minimum free **28,272 B**, minimum largest block **26,216 B**, maximum fragmentation **12%** in first 1024-sample window (`docs/V05_MEDIA_WIRE_HOST_GATE.md:7`) | Owner-reported, historical, finite window on current private image. No concurrent native media, no future build headroom, no continuous soak. |

## Risk register

| ID | Risk / source evidence | Gate |
|---|---|---|
| R1 Critical | Post-handler length check cannot prove early HTTP body allocation bound (`FirstBootBridge.cpp:251-260`). Oversize/slow input may exhaust heap or monopolize the cooperative loop. | **BLOCKED** for an active media route pending pinned-core parser evidence and bounded ingress tests. |
| R2 Critical | Existing Digest nonce is shared; browser GET cookie is read-only (`FirstBootBridge.cpp:78-85,159-177`). V0.5 fake auth is no proof (`media_wire_v1.py:181-210`). | **BLOCKED** pending route-specific auth, nonce/replay/CSRF and concurrent-client test design. |
| R3 High | 8192-byte cover plus staging/retained copy, HTTP buffers and paint contend with owner-observed 26,216-byte lowest largest block (`V05_MEDIA_WIRE_HOST_GATE.md:7,28-33`). | **HOLD** until phase-specific allocation/fragmentation tests; allow a text-only fallback. |
| R4 High | `server.handleClient()` precedes four-card paint and watchdog service (`FirstBootBridge.cpp:468-480`); no media interruption or slow peer behavior has been measured. | **HOLD** until sustained mixed metrics/media/browser host and later authorized device observation. |
| R5 High | Overlay expiry needs a deliberate redraw; current loop repaints only on metrics/stale change (`FirstBootBridge.cpp:468-472`). | **HOLD** until isolated compositor tests prove five-second return, invalid-cover revocation and four-card freshness preservation. |
| R6 High | Exact OEM application-only return remains a separate optional write route (`FirstBootBridge.cpp:440-454`, `FactoryRollback.cpp:85-176`); generic updater disabled. | **BLOCKED** for any firmware/FS/OTA policy change without a new owner-specific review and approval. |
| R7 Medium | Fixed 1024 one-second heap samples miss short-lived peaks; default build has no observer (`ShinoHeapDiagnosticCandidate.h`, `NativeOtaHeapReview.h`). | **HOLD** on claims of RAM safety or continuous endurance. |
| R8 Medium | Owner evidence confirms current four metric LCD and PC-local V0.4 preview, not artwork on the physical ST7789 (`companion/README.md:5`, PR #25, `V05_MEDIA_WIRE_HOST_GATE.md`). | **HOLD** on physical color/layout/legibility claims. |

## GO / HOLD / BLOCKED decision

- **GO now:** source-only specification, offline native host probes, static call-path and allocation analysis, emulator concurrency/failure tests, documentation. Preserve PR #20, installed review-003, V0.1 tray/autostart and external worktrees.
- **HOLD:** a separately reviewed *unconnected* candidate receiver/compositor design or compile-only experiment until R1-R5 are demonstrated with bounded memory and metrics parity. An offline compile is not device safety evidence.
- **BLOCKED:** registering a real media/image HTTP route, contacting the SmallTV, changing production auth, changing OEM-return/native OTA/FS safeguards, building an owner installation packet for this feature, or flashing. Each later boundary needs the applicable independent owner decision. No USB/UART/PCB recovery dependency is introduced.

## Recommended sequence

1. Freeze and diff the actual V2.1 active call path and pinned `ESP8266WebServer` parser behavior. Build source-executed host probes for header/body limits, duplicate fields, early disconnect and timeouts before selecting request framing.
2. Specify a separate versioned receiver interface with real Digest and transaction/nonce binding, authorization before storage, one pending transfer, absolute eight-second deadline and deterministic rejection. Keep the V0.5 wire codec on PC; avoid `arg("plain")` for unproven large bodies.
3. Create an unconnected native state machine and mixed-load host tests: continuous accepted/rejected metrics, stale transition, concurrent dashboard GET, all tile/CRC/SHA/replay/failure cases, and return to four cards after five seconds. Verify invalid media cannot mutate `FslessMetrics` or extend its TTL.
4. Audit stack/static/heap and LCD pixel path in a separately versioned candidate build. Measure worst phase and largest free block under concurrent workloads; choose a smaller image or text-only mode if 8192 B cannot fit with margin. Keep FS/OTA/OEM boundaries unchanged.
5. Only after those gates and a new exact image/source review, seek individual permission for any owner-device observation or installation. Physical LCD color/timing and installed safety remain unverified until then.
