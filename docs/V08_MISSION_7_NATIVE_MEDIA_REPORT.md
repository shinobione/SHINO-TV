## Architecture and legacy preservation

Mission 6C proved an architectural blocker and denied authorized multipart. Its parser/auth candidate is NOT adopted. The new generator derives from Mission 6A and fingerprints Core 3.1.2. Its `Parsing-impl.h` is exactly Mission 6A's prefetched-first-line adaptation of the pinned parser; Basic/Digest, body parsing, route callbacks and conditional OEM multipart retain that compatibility domain, including their known security defects. Production `firmware/`, `companion/`, `simulator/`, previous tools, documents and public vectors remain unchanged.

The generated WebServer owns one current client and the first-line buffer. The corrected namespace reservation runs first. Legacy lines enter the same existing parser with exact raw first-line bytes. Reserved media candidates go exclusively to the separate `m7::Ingress`: they never call legacy header/body/parser/handler code. Encoded, query, malformed and ambiguous media targets reject in the media branch; no normalization changes a signed target. The trusted `setOfflineMedia` pointer is null by default. With null, the media namespace remains DENY-ALL. No media handler is registered in the route table.

The owner retains 64-byte incremental first-line reads, 130 wire bytes, the independent absolute 2000-ms clock, raw legacy handoff, strict **elapsed >30-ms** no-data ready/full-queue contention and once-only cleanup. Media continuation also drains at most64 bytes/poll and applies that contention predicate after draining. Completed first lines hand off on a subsequent poll, so header/body work cannot add a second64-byte slice to the first-line poll. An idle owner services challenge expiration and the transfer deadline even without a request. Terminal media closes release the body buffer, including FIN/outer disconnected-owner paths.

## Bounded HTTP and Gate 1

Only exact `POST /api/v2/bridge/media/{begin|tile|commit|abort}/{32 lowercase hex} HTTP/1.1` lines enter header receipt. Epoch and sequence are nonzero. The media profile retains 1024 total wire header bytes including request line, 256 bytes/field line, at most12 fields, strict CRLF/ASCII and the exact seven allowed unique fields. Profile1.1 outer SP/HTAB OWS, DNS/IPv4 authority grammar/lowercase/default-port removal and permitted SF inner-list/parameter spaces normalize before proof; configured authority is independently supplied in canonical form. Content-Digest stays raw canonical because it is covered. Signature is decoded to exactly64 bytes, including omitted padding accepted by the retained SF adapter. Required values are media-wire-v2 Content-Type, canonical length40–552, `Connection: close`, canonical SHA-256 digest and the exact frozen ordered Signature-Input components/parameters. Unknown/duplicate fields and SF members/parameters, Transfer-Encoding, Content-Encoding, Expect, folded lines and trailers cannot pass. This implements the narrow fixed profile, not a general RFC Structured Fields library. Target/body shape limits match the frozen profile.

Header storage is fixed. Gate1 validates the trusted fixed roster's enabled/revoked/media-role/operation, exact live epoch and challenge principal/revision/expiry before ECDSA. Unknown/used/expired challenges invoke zero ECDSA. Real proof is followed by a fresh clock sample and serial/revision/epoch/expiry recheck, then a single consume. Bad proof leaves the live challenge intact. Principal state changes and validated key rotation increment revision and invalidate challenges; revocation is terminal. A proof ticket is rechecked before allocation, every body read and admission. Disable/enable, same-key rotation and epoch reset do not revive proofs. Serialization is the single synchronous WebServer owner; these APIs are trusted lab calls, not interrupt-safe or remotely callable provisioning.

`MediaCrypto.h` calls the pinned BearSSL `br_ecdsa_i15_vrfy_raw(&br_ec_p256_m15, hash,32,&pk,signature,64)`, with `BR_EC_secp256r1` and a validated65-byte SEC1 uncompressed public point. Signature encoding is IEEE P1363, fixed32-byte r followed by32-byte s, not DER. SHA-256 uses `br_sha256_*`; signature-base components are streamed without a second large string. Exact retained public signature/base-hash vectors pass. [BearSSL's API reference](https://www.bearssl.org/apidoc/bearssl__ec_8h.html) documents this verifier and return convention; the checked source/toolchain, not current online documentation, governs this build.

The framework reports BearSSL revision `b024386`. The manifest pins all consumed host crypto C/header/config inputs. PC compilation uses the same verifier and P-256 implementation with `BR_LOMUL=1, BR_SLOW_MUL15=1`: the portable C multiplier is necessary because the framework's default references Xtensa-only `mul20`/`square20` assembly. Native links use the framework library and default assembly. PC interoperability therefore does not execute the native assembly or certify its runtime timing. No bespoke cryptography is introduced.

## Gate 2 and staging

Only after Gate1 succeeds does the receiver allocate the exact declared body and incrementally read it. Maximum552 bytes. It hashes exact received bytes, compares32 digest bytes without early exit, requires literal `53 54 56 37`, version2, flags0, operation/epoch/transaction agreement, payload length/CRC and operation/index limits. Partial bodies, buffered trailing input, changed content and malformed records fail before application admission. A failed Gate2 preserves existing staging. Successful Gate1 consumes its challenge even if subsequent body validation fails.

The trailing-input rule matches Mission 6B: bytes already buffered beyond declared length reject before admission without consuming them; terminal close prevents their later dispatch. Future TCP bytes cannot be predicted by a Content-Length receiver. The candidate does not require client FIN and does not claim to detect bytes that arrive after completion/close. The absolute2000-ms request deadline is checked at entry, during reads, after proof and before mutation. Native synchronous crypto, SHA/image work and WiFi operations have no measured wall-time bound.

`MediaReceiver.h` validates the unchanged16-field canonical UTF-8 metadata schema, exact alphabetic serialized bytes, dimensions0/32/48, text/progress limits, tile count, RGB565LE/NONE and final hash declaration. Temporary JSON storage has a hard4096-byte native arena (8192 on64-bit PC because ArduinoJson slots are larger); allocation/schema/canonical failure rejects. The arena dies before image staging allocation. No original wire-v2 file is edited.

One pending transaction has principal ownership, a high-water sequence, absolute8000-ms transfer clock (exact8000 valid,8001 expired, including rollover), sequential512-byte tiles, identical-duplicate idempotence and terminal conflict/order/incomplete/hash failure. Accepted Begin clears prior sink ownership at the same rollback/high-water boundary as wire-v2. Commit hashes the staging allocation and moves that same pointer into an inert sink; no full-image Commit copy. Abort clears an owned transfer. The sink retains canonical metadata and image ownership, with no LCD call or physical display policy. Display timing/overlay qualification is outside this receiver seam.

## Provisioning and freshness boundary

Explicit synthetic/public provisioning only: up to16 unique principal IDs (1–24 lowercase/digit/underscore/hyphen characters), validated SEC1 P-256 public point, explicit enabled/revoked/media-role and four-bit operation mask. No production private key, enrollment file or configuration endpoint is introduced. Retained vectors use their retained public key. Additional complete0/32/48 flows use an ephemeral Node test signer in memory; its private key is never exported, logged, saved, committed or uploaded. Evidence retains only the generated public point and signed public messages.

The challenge issuer is a trusted `issue(principal,nonce,now,ttl)` interface with four global slots, two per principal,22-character base64url-alphabet nonce and TTL1–60000ms. An ordinal watermark requires strictly increasing nonce values across all principals even after consume/sweep/lifecycle changes; failures preserve the watermark. Expired slots are swept by the owner. This is the accepted narrow ordered lab contract, not a production random issuer or an entropy claim. R3 remains PARTIAL.

Reboot requires a strictly greater64-bit epoch; `Ingress::reboot` clears tickets/body, challenges, watermark and receiver transaction state under the same owner. Roster revocation remains terminal in that live Authority. A real deployment must persist monotonic freshness and revocation/key policy before accepting media; a freshly reconstructed volatile Authority at an old epoch can replay an old public signature if its nonce is reintroduced. No offline fixture proves power-loss freshness. Tick subtraction assumes the owner services clocks within the32-bit wrap horizon; multi-wrap outages are not qualified. R10 remains BLOCKED for owner-approved provisioning, custody, enrollment/revocation authority, entropy and challenge delivery.
