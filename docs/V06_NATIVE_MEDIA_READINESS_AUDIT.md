## A2. Confirmed framework parser ordering — P0 is a REAL blocker, not just a suspicion

The frozen \`platformio.ini\` declares framework package \`3.30102.0\`, corresponding to upstream Arduino ESP8266 **3.1.2**. I examined its official [tag 3.1.2](https://github.com/esp8266/Arduino/releases/tag/3.1.2), dereferencing annotated tag \`e1c8e27b63dd05412a4e690d61f7b3d160684297\` to upstream source commit **\`210897ef83305496947c4e73c937bab52a33cb48\`**. This is source-based evidence for the pinned upstream, **not** a local byte-for-byte installed-framework verification.

- [ESP8266WebServer-impl.h:338–346](https://github.com/esp8266/Arduino/blob/210897ef83305496947c4e73c937bab52a33cb48/libraries/ESP8266WebServer/src/ESP8266WebServer-impl.h#L338-L346) explicitly calls \`_parseRequest(_currentClient)\` **before** invoking \`_handleRequest()\`, where the ordinary route's completed handler executes.
- [Parsing-impl.h:115–188](https://github.com/esp8266/Arduino/blob/210897ef83305496947c4e73c937bab52a33cb48/libraries/ESP8266WebServer/src/Parsing-impl.h#L115-L188): for a non-multipart POST, it parses \`Content-Length\` via \`headerValue.toInt()\`, calls \`readBytesWithTimeout(..., contentLength, plainBuf, HTTP_MAX_POST_WAIT)\` and then stores an additional \`plain\` request argument. [Parsing-impl.h:38–41](https://github.com/esp8266/Arduino/blob/210897ef83305496947c4e73c937bab52a33cb48/libraries/ESP8266WebServer/src/Parsing-impl.h#L38-L41) routes the full advertised body into a \`String\` via \`S2Stream(data)\`. The ordinary route's \`requireAuth()\` and length check in V2.1 \`acceptMetrics()\` therefore happen **after the server has read/buffered the POST body**. This is an important source-observed constraint even though the current numeric sender is small/known.
- [Parsing-impl.h:348–430](https://github.com/esp8266/Arduino/blob/210897ef83305496947c4e73c937bab52a33cb48/libraries/ESP8266WebServer/src/Parsing-impl.h#L348-L430) separately handles multipart/form upload and invokes a registered upload callback **during parsing**; that path has its own argument/upload allocations and is currently reserved for the separately reviewed exact OEM return. It is **not** an automatic safe media ingress, and V0.6 must not borrow or alter it.
- [ESP8266WebServer.h:61–65](https://github.com/esp8266/Arduino/blob/210897ef83305496947c4e73c937bab52a33cb48/libraries/ESP8266WebServer/src/ESP8266WebServer.h#L61-L65) pins \`HTTP_MAX_POST_WAIT\` to **5000 ms**. This is an HTTP read wait, **not** proof that a new 8-second V0.5 multi-request transfer meets watchdog or metrics deadlines.

**Decision for this audit:** the tempting new \`server.on("/api/v1/media/...", HTTP_POST, [] { if (!requireAuth()) return; if (server.arg("plain").length() > 512) ... })\` route is **NOT ACCEPTABLE** as the proposed allocation-before-auth boundary. Do not add it or use the numeric metrics endpoint for art. A possible later separate authenticated, length-limited ingress must bound request line, headers, Content-Length, duplicate/ambiguous framing, body bytes, timeout and caller auth **before any large body allocation**, then emulate the real pinned framework/underlying client behaviour with negative socket tests. We have **not** implemented or approved such native ingress in V0.6; the physical deployment gate remains closed.

## B. Heap admission: conditional, not yet demonstrated

Owner-observed first V2.1 review-003 heap run: lowest observed free **28,272 B**, lowest largest allocatable block **26,216 B**, max sampled fragmentation **12%** (limited to first **1024** samples). This is a historical observation on the **existing image without media receiver**, not a validated future margin or simultaneous allocation snapshot. The GET/status serialization itself consumes additional heap; prior minima are not an in-flight HTTP parser measurement.

| Experimental envelope | Logical bytes | Evidence needed before a native implementation |
| --- | ---: | --- |
| PC-preconverted RGB565 64×64, little-endian | 8,192 | Display legibility and image RAM residency; static allocation versus heap must be chosen. |
| One incoming ordered tile | 512 | Measure **actual** ESP8266 WebServer/client parsing+headers and network buffer lifetime, not just payload. |
| Canonical metadata envelope | max 512 | Bound received HTTP content **before** dynamic JSON/body read. Avoid duplicate String/JsonDocument copies. |
| One pending cover (never old+new concurrently) | 8,192 | V0.6 host model revokes previous accepted cover **before** staging another, so logical artwork storage cannot reach 16,384 B. Not proof of native heap allocation. |
| Full-screen RGB565 240×240 | 115,200 | Explicitly **out of scope** on ESP8266 for this feature; no full framebuffer proposed. |
| V0.5 host transaction deadline | 8 s | This is a **proposal only**; native HTTP timeout and watchdog handling have not been built. |
| Music overlay | 5 s | PC-host state machine tested, physical redraw and timing remain unproven. |

An additive 8,192+512+512 = **9,216 bytes** is only a simple logical payload budget, **not total RAM**. Cannot subtract it from historical free heap to announce safety: network body buffers, Digest state, ArduinoJson, allocations, stack, user-interface calls, fragmentation and one pending transaction can overlap. Candidate must log **per phase** (idle metrics, auth challenge, header validation, Begin, each tile, commit/hash, drawing, interrupted transfer, post-cleanup, OEM status GET) while a *single real* 2-second metrics sender runs. Never rely on median free memory; compare the lowest free and largest contiguous block with measured simultaneous peak and a documented reserve. No threshold is approved yet. When uncertain, **no cover / text-only** is the safe candidate.

## C. Concrete V0.6 changes in this branch — HOST ONLY

1. Read-only static regression tests in `tools/test_media_v06_frozen_source_gate.py` assert real frozen ESP8266 entry path, route set, numeric metric POST, four cards and staleness, separate signed-OEM guard, capped heap observer and pinned toolchain. Tests target actual checked-in source rather than made-up firmware routes; they cannot prove runtime header parser or exact installed private BIN.
2. Hardened Python **host emulator** in `companion/media_wire_v1.py`: when starting a new authenticated/validated transfer, release prior accepted artwork *before* allocating the next 8192-B staging buffer. During staging display logic is PC HEALTH. A verified same-track progress refresh restores its **original** overlay deadline without extending it; a new playing identity starts a fresh five-second overlay. Invalid or expired staging discards all previous artwork and stays on PC HEALTH.
3. New `companion/test_media_v06_resource_stress.py` runs deterministic 64-song synthetic cycles mixing coverless, interrupted and complete transfers, bounds logical staged+committed cover to one 8192-B image, verifies recovery, same-track timing, and four-metric independence. No real socket to the physical device and no credentials are loaded.

**One design note:** this resource policy may create a brief PC HEALTH return during an actual future cover refresh. Whether to optimize metadata/progress without reuploading unchanged art is a separate versioned protocol decision; never silently retain two full images or claim zero-flicker without testing.

## D. REQUIRED future gates (none silently passed)

- **P0 — Body preallocation/auth audit:** **confirmed issue:** stock Core 3.1.2 ordinary non-multipart POST buffers the declared body into `plainBuf` before `_handleRequest()`, so a plain `server.on(...HTTP_POST...)` handler's Digest/size checks happen too late to serve as an early memory bound. Review alternate separately authenticated ingress and exact header parser, Content-Length and Transfer-Encoding policy, deadlines, duplicate/ambiguous headers, error close semantics, nonce binding and any preauth allocation; build a real-framework/pinned-client loopback probe and prove rejection **before accepting/allocating an 8192-B image**. No implementation in this PR.
- **P1 — Native memory/renderer gate:** independently versioned compile-only prototype, measured map/firmware bytes and per-phase/free-largest-block/fragmentation under concurrent numeric telemetry; optimize only if measurement supports it. No automatic filesystem writes, no framebuffer and no sharing stale/reused art. Verify forced interrupted-transfer cleanup and watchdog plus OEM status still work.
- **P2 — Proper auth/replay contract:** replacing `auth_verified=True` in Python with actual approved per-route device-side Digest, nonce and transaction lifetime; browser read cookie must NEVER authorize media or OEM upload. Test auth failure after a staged transaction, source switching, blank metadata and stale messages.
- **P3 — Owner decision:** produce exact proposed source/image hashes, expected impact on current 4-value UI, fixed device state, verified OEM application return path, and clear remaining Wi-Fi-only brick risk. A new physical OTA and restart each need distinct explicit owner authorization. USB-C remains **power only**; do not require UART, pogo pads or solder in normal work.
