# SHINO // TV V0.8 Mission 3 — protocol decision

**Internal research decision: media-http-profile-1.1. Production authentication remains BLOCKED.** Base is `273b386070802cc6aba0a16c8cd8b5a6dc7abf00`. This decision amends the Mission 1 HTTP admission policy; it changes neither media-wire-v2 nor the frozen V0.5 codec. The original host verifier and seven public vectors remain byte-for-byte intact. ## Standards decision and interoperability boundary

Use RFC 9421 signatures and RFC 9530 Content-Digest with the field-specific types originally defined using RFC 8941. Use an RFC 9651 parser, then enforce those older field types and the narrower application policy. RFC 9651 obsoletes RFC 8941, is designed for backward parsing compatibility, and does **not** automatically permit new types in older field definitions. Date and Display String are excluded here, including extension parameters. [RFC 9651 §2 and Appendix D](https://www.rfc-editor.org/rfc/rfc9651.html#section-2), [RFC 8941](https://www.rfc-editor.org/rfc/rfc8941.html).

RFC 9421 requires lowercasing the authority hostname and omitting the default port. Signature parameters enter the base through Structured Fields serialization; covered raw HTTP fields without `;sf` retain their field-value representation after HTTP normalization. The signature format for `ecdsa-p256-sha256` is 64-byte `r || s`. [RFC 9421 §§2.1, 2.2.3, 2.3, 3.3.4](https://www.rfc-editor.org/rfc/rfc9421.html#section-2.2.3).

The host adapter uses pinned [structured-headers 2.0.3](https://github.com/evert/structured-header) parsing/serialization and Node's real P-256 verifier. Dependency integrity is in `experiments/v08_protocol/package-lock.json`; lifecycle scripts are disabled. This is an interoperability experiment using an external parser, not independent security approval or a selected native dependency. The bounded admission adapter is not a general RFC parser or conformance suite; its caps deliberately exclude larger otherwise legal HTTP/SF values.

**Explicit policy version change:** Mission 1's fixed spelling/whitespace and raw Host comparison are profile 1.0 research behavior. Profile 1.1 admits HTTP outer OWS, valid SF spacing, hostname case variation and an explicit default `:80`, subject to the rules below. This expands admission and changes component extraction for authorities outside the original fixture. Deployments must select an agreed profile explicitly; no tag-based negotiation or silent production upgrade is specified. The fixed `tv.test` requests retain exactly the same signature bases, hashes and signatures in both profiles. The media tag and binary version stay unchanged. Adding `;sf` to covered digest, changing component/parameter order, supporting TLS/proxies/IPv6, or changing the tag requires separately versioned vectors and review.

## Exact profile 1.1 contract

1. Direct HTTP/1.1 origin-form, locally known cleartext `http` scheme only. No proxy, forwarded authority/scheme, HTTP/2 or HTTP/3 reconstruction. Request line is exactly `POST /api/v2/bridge/media/{operation}/{tx} HTTP/1.1\r\n`. Operations are lowercase `begin|tile|commit|abort`; transaction is 32 lowercase hex characters with nonzero eight-byte epoch and eight-byte sequence. No query, fragment, escaping, normalization, aliases, doubled/trailing slash or extra request-line whitespace.
2. The wire bounds remain 130 request-line bytes including CRLF, 256 bytes per field line including CRLF, 1,024 bytes through CRLFCRLF and 12 fields. Exactly seven unique case-insensitive field names are required: Host, Content-Type, Content-Length, Content-Digest, Connection, Signature-Input, Signature. Reject all duplicates **before** constructing a field map; reject all other fields, including Authorization, Transfer-Encoding, Expect, Content-Encoding and Trailer. Reject obs-fold, bare LF, stray CR, control characters and whitespace before the colon. SP/HTAB outer OWS after the colon and at the end of a value is stripped; internal whitespace follows each field's rules. No tabs are admitted in the request line.
3. Host is an ASCII DNS name with 1–63 character LDH labels and total length ≤253, or canonical dotted IPv4 without leading zeros. Optional port is canonical decimal 1–65535 without leading zeros. Lowercase host; omit `:80`; retain every other explicit port. Reject bracketed IPv6, userinfo, trailing dot, IDNA/non-ASCII and malformed labels rather than invent normalization. The normalized authority must equal the independently configured authority; `tv.test` is a public fixture, not an enrollment decision. Test `TV.TEST:80` verifies an existing signature for `tv.test`.
4. Content-Type is exactly `application/vnd.shino-tv.media-wire-v2`; Connection is exactly `close`. Length is canonical unsigned decimal 40–552, with Tile exactly 552, Commit/Abort exactly 40, Begin 41–552. No multipart, compression, chunking, trailers or connection reuse.
5. Parse all three SF fields using the pinned library. Before parsing, the one-member profile rejects unquoted dictionary separators and repeated parameter keys so last-value overwrite cannot conceal duplicates. Quoted delimiters are data. Component parameters are forbidden, so the allowed parameters have one outer scope. After parsing require exact names, types, sizes and shape; unknown extension parameters and all extra members fail.
6. Signature-Input has one `sig1` Inner List containing, in order, the six unparameterized **strings** `@method`, `@request-target`, `@authority`, `content-type`, `content-length`, `content-digest`. Outer parameters are exactly, in order, string `alg="ecdsa-p256-sha256"`, string `keyid` matching `[a-z0-9_-]{1,24}`, string `nonce` matching `[A-Za-z0-9_-]{22}`, string `tag="shino-tv-media-v2"`. SF-permitted Inner List/parameter spaces serialize canonically. Token, boolean, date or display-string substitutes fail. Reordered parameters are outside this profile; parameters must not be sorted and then treated as an unchanged signed base. An alternate valid order would need a new sender signature and policy agreement.
7. Signature has one unparameterized `sig1` Byte Sequence with exactly 64 decoded bytes. Content-Digest has one unparameterized `sha-256` Byte Sequence with exactly 32 bytes and must match its canonical SF spelling after outer HTTP OWS removal. This preserves the original **raw covered** digest value; the adapter never silently converts a noncanonical signed raw digest into another value. Digest is over every binary body byte, including the 40-byte record header. A valid signed declaration still needs recomputation after receipt. [RFC 9530 §2](https://www.rfc-editor.org/rfc/rfc9530.html#section-2).

The canonical signature base is the following ASCII sequence with LF separators and **no final LF**:

```text
"@method": POST
"@request-target": /api/v2/bridge/media/{operation}/{tx}
"@authority": {normalized configured authority}
"content-type": application/vnd.shino-tv.media-wire-v2
"content-length": {canonical decimal}
"content-digest": sha-256=:{canonical 32-byte base64}:
"@signature-params": ("@method" "@request-target" "@authority" "content-type" "content-length" "content-digest");alg="ecdsa-p256-sha256";keyid="{keyid}";nonce="{nonce}";tag="shino-tv-media-v2"
```

## Gate separation and state constraints

Gate 1 consumes only the bounded header block. Require an own registered principal entry, a real EC prime256v1 public key, allowed operation, matching current epoch, valid signature and current unused unexpired principal challenge. Consume the challenge after proof; failure cannot allocate/read body or alter unrelated pending work. The reused challenge model has two outstanding entries per trusted key, explicit expiry sweep and reboot reset. It is a model with provisioned fixture inputs, not entropy, issuance, persistence or production authentication. Host buffers already contain fixture bodies; zero `bodyReads` proves API ordering, not TCP receive-buffer behavior.

Gate 2 allocates 40–552 bytes only after Gate 1, reads exact length, verifies body digest and then fixed-header identity, operation, flags, length, CRC and shape. All 16 target transaction bytes and the epoch must agree with the repeated binary header. The unchanged V0.7 receiver separately enforces canonical Begin metadata, variant-dependent next tile, pending principal ownership, single pending transaction, replay high-water, final image SHA-256 and no-copy ownership transfer. The HTTP lab does not dispatch to that state machine or claim its lifecycle qualification as native behavior.

Close every media connection. Reject trailing bytes **already buffered** in the host input; late arrivals cannot become another request because the connection closes. Do not wait for peer FIN before replying. A literal guarantee that every byte sent later is observed/rejected is impossible to infer from these models; native FIN/RST/half-close/buffering tests remain HOLD. CRC, image SHA, cookies, Basic/Digest, transaction sequence and track keys do not authenticate media.

## Qualification and unresolved decisions

Eight new tests pass alongside all eight retained crypto tests. Every retained public signature verifies with the new SF parse/serialize path and its original fixed base hash. Additional tests cover authority/OWS/SF spacing, raw duplicate preservation, malformed parameters and types, forbidden framing, principal operation, wrong public point, epoch, expiry, nonce replay and signed binary/body mismatches. No private key is generated or retained. This establishes host interoperability for this profile's fixtures, not general RFC compliance or native Gate 1 proof.

**GO:** profile 1.1 offline decision and public-vector compatibility. **HOLD:** independent RFC/security review, differential testing against another implementation and broader published RFC vectors, final production authority/optional-field policy, native SF/base builder and exact socket framing. **BLOCKED:** production key enrollment/revocation and PC custody, unpredictable fresh boot epoch and challenge issuance/rate limiting/entropy failure, native verifier timing and memory, active media receiver. A 64-bit epoch does not prove nonrepetition. Challenge delivery and trusted transport are still undecided; signatures provide no confidentiality. No production authentication is implemented.
